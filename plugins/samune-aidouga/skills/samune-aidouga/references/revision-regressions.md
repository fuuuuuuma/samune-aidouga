# 修正箇所と保持箇所を独立させる

案件の具体的な値と発言は対象チャンネルの `memory/corrections.jsonl` と承認記録を読む。他の利用者の配色・人物・コピー・数値を初期値にしない。

| 修正内容 | 分けて記録・検査すること |
|---|---|
| 文字を大きくする | 座標・字高と、塗り・フチ・影を別項目で固定する |
| 透過を変える | 線幅と不透明度を別にする。正確なレイヤー値と生成画像の見た目を区別する |
| 文字色だけ変える | 対象語と新色だけ変更し、別の文言や配置を保つ |
| ロゴを差し替える | 正式原図の形・比率・指定配色を確認し、旧素材の条件を残さない |
| 一部の人物を調整する | 人物別に変更許可を記し、指示のない人物の顔サイズ・ポーズを保持する |
| 背景を調整する | 背景変更の許可と、文字・人物・ロゴの保持を別にする |
| ぼかしを強める | 対象範囲と認識目標を示し、周囲の文字までぼかさない |
| 以前の文字へ戻す | 戻す採用稿を特定し、その字形・装飾を参照する |
| 他は変えない | 変更可能な末端項目を列挙し、元画像と実画像の差分を目視する |

修正2案はどちらも累積指示を満たす。最後の一文だけで以前の条件を消さない。JSONの一致だけでは実画像の保持を証明できない。完全な画素保持が必要なら対応領域の比較で確認する。

採用された画像を勝手に作り直さない。承認済み画像に別の問題が見えても、今回の保持指定を破って全面修正しない。継続する修正は対象のチャンネル／シリーズに保存し、今回だけの指定は案件へ残す。

人物素材、実画像の目視、寸法、原本と書き出しの区別は [共通確認](global-feedback.md) を使う。
