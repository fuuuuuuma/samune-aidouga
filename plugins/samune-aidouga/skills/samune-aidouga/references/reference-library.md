# 任意の資料ライブラリと全件レビュー

利用者がローカル資料・複数参考集を追加した場合に使う。通常の制作では保存済みプロファイルと近い参考2〜4枚を再利用する。以下の全件レビューは、利用者が依頼した場合、または明示設定した production-policy.json で求められる場合だけ行う。

## 保存と優先順位

データ場所は `DATA_ROOT` とする。利用者が保存先を指定した場合はそれを使う。以下のパスはこのデータ場所を基準とする。

- `reference-library.json`：参照チャンネルとローカル資料、画像一覧への経路。
- `production-policy.json`：優先チャンネル、毎回の全件確認、恒常ルールと案件限定ルールへの参照。
- `reference_collections/<id>/`：URL未確定の提供画像。UC IDを作り話で付与しない。
- `channels/<UC ID>/`：確認できた公開チャンネル。
- `pattern-library.json`：根拠画像付きの構図・文字・配色・影・フチの組み合わせ。
- 案件の `reference_review/`：今回の全件一覧、確認記録、候補選択。

同一チャンネルの作品から構図・色の原則を学ぶことと、その背景画像をそのまま流用することを分ける。他チャンネルの人物・固有キャラ・ロゴ改変・事実や数値を自動転用しない。優先チャンネルのフォントと階層を基準に、外部資料は補助的な構図候補として使う。ユーザーが制作対象チャンネルを明示した場合は対象の独自性を尊重する。

## ローカル資料を追加する

同スキルの専用Pythonで `scripts/reference_library.py import-local --source-dir <提供フォルダ> --out-dir <reference_collections/id> --name <資料名>` を実行する。元ファイルは変更せず、画像を元バイトで保存し、ハッシュ・寸法・重複・失敗を記録する。提供フォルダの範囲と、そのチャンネルの全公開投稿を混同しない。

PSDは表示済み統合画像・アートボードと、文字/親グループ/境界線/影/グラデーション/マスク/配置を解析する。解析時の可視性と効果の有効/無効を保存する。非表示のデザインメモを利用者の指示と混同しない。PNG/JPGだけの画像では正確なフォント名や効果数値を断定せず、候補と見た目の特徴として保存する。

## 全件レビューを依頼された場合の手順

1. 今回の原稿・ラフ・最新承認画像を確定し、優先設定と修正履歴を読む。ローカル資料の追加や公開サムネの明示更新依頼がある場合は差分を先に取り込む。
2. `scripts/reference_library.py prepare --library <reference-library.json> --out-dir <案件/reference_review/今回の依頼ID>` を実行する。古い確認記録を今回のものとして上書きしない。
3. `review-index.json` の全ページを、画像表示ツールで実際に目視する。枚数が多い場合は複数回に分け、見落としなく全ページを確認する。生成しただけでは閲覧済みにならない。既知の型でも省略しない。
4. 各ページを見た後、`page-reviews.jsonl` に `page_id`、`viewed:true`、`at`、具体的な `notes` を記録する。確認前の一括チェックは禁止。同じ依頼内でページを再構成した場合、同一画像の既存確認へ出典を明記できるが、新しい依頼への使い回しは禁止。
5. `scripts/reference_library.py verify --review-dir <今回のフォルダ>` で欠落0を確認する。これは記録の検査であり、画像を見た証明を自動生成する処理ではない。
6. 優先チャンネルの候補2〜4枚を原寸で見比べる。新しい構図に有効な他チャンネル例があれば追加で確認する。確定フォントが必要なら対応PSD設定と実フォントの利用可否も確認する。
7. `design-decision.json` に以下を残してから完全版生成JSONを作る。

必須の選択記録：今回のテーマ、制作対象/優先チャンネル、全件確認記録への経路、比較候補のID、採用するパターン、候補を選んだ理由、書体の正確な名称と根拠または未確認、導入/結論/数字のサイズ関係、文字塗り、グラデーション、境界線の順番・色・太さ、影の色・距離・ぼかし・不透明度、ロゴ/キャラ/人物の元資料、背景の方針、保持項目、今回だけの例外。

単一の型を全企画に当てない。比較、手順、ツール紹介、検証、対談、警告、速報のどれかを内容から判断し、使う型を決める。ラフの構図は今回の明示指示として優先する。

初回A/B/Cの3案、修正R1/R2の2案は、同じ依頼の参考確認を共有できる。案ごとの狙い・参考・許された変化は別々に残す。詳細は [ラフからの制作](rough-to-delivery.md)、判断の言語化は [デザインの判断理由](design-reasoning.md)。

## 修正学習と引き継ぎ

- 採用された画像だけを成功事例にする。比較案のどちらを指すか一意でない時は、直前の表示画像など解釈の根拠を記録し、全比較案を勝手に採用済みにしない。
- 継続指定はチャンネル設定、当該画像だけの太さ・透過・ブラー・色違いは案件設定へ置く。一般化できるのは独立して固定する手順であり、全案件に同じ数値を強制することではない。
- 各文字ブロックの役割と装飾を分ける。ロゴは正式素材の形と指定配色を守る。キャラの装飾とロゴの変形を混同しない。
- 文脈を整理する前に、採用画像・プロンプト・修正条件・参照一覧・未完了範囲・次の入口をデータ側へ保存する。スキル本体へ過去チャットや大量の画像を埋め込まない。
- 「学習済み」は資料を確認して再利用可能な記録を作った意味。モデルの再訓練、CTR改善の実証、完全なピクセル再現とは区別する。
