# チャンネル登録・全件収集・傾向分析

## 対象の確定

標準入力はユーザー指定のYouTubeチャンネルURL。URLを直接開いて正式名・ハンドル・チャンネルIDを取得し、名前検索を挟まずに登録する。URLで一意に特定できたら名前やURLの再確認を求めず、収集・分析まで進める。

- `https://www.youtube.com/@ハンドル`：公開ページまたは1件限定のメタデータからchannel_idを取得。
- `https://www.youtube.com/channel/UC...`：URLのIDを公開ページのチャンネル情報と照合。
- 旧形式の`/c/...`・`/user/...`：リダイレクト後のチャンネル情報からIDを確定。
- 末尾の`/videos`・`/shorts`・`/streams`、共有用のクエリが付いたURL：チャンネルを特定してから正規URLを保存する。「全部」の依頼では末尾のタブに収集範囲を限定しない。
- YouTube以外のURL、リンク切れ等でチャンネルを特定できない時だけ、正しいチャンネルURLを求める。動画単体のURLなら投稿元を確認し、そのチャンネルを対象にする依頼だと分かる場合だけ進める。

URLがなく名前だけの場合に限り、名前検索で候補を絞る。同名候補が残る時だけ候補リンクを示して確認する。参考チャンネルと制作対象チャンネルを混同しない。

チャンネルIDが公開ページから取得できない時は、判明したハンドルURLを次のように1件限定でメタデータ取得して `channel_id` を確認できる。これはIDの照合用で、全件収集ではない。シェル引数は適切に引用する。

```bash
python3 -m yt_dlp --ignore-config --flat-playlist --skip-download --playlist-end 1 --dump-single-json 'https://www.youtube.com/@確定ハンドル/videos'
```

動画タブがない場合は公開されている shorts / streams タブで照合する。yt-dlpが使えない・検索不可の場合はYouTube URLを一度だけ求めるか、既存のユーザー提供資料から分析できる範囲を進める。

## 全件の定義

「全件」は実行時に取得可能な公開動画・Shorts・ライブ一覧に掲載された動画IDの現在のサムネ。非公開・削除済み・一覧に載らない限定公開・メンバー限定・地域制限の画像、過去に差し替えられた全サムネ、A/Bテストの全画像は保証しない。

- RSSの直近分や最初の画面だけで全件としない。動画数の上限を設けず、yt-dlpにページ送りを任せる。
- `--limit 0` が標準。件数制限は試験・ユーザー指定時だけ使い、結果は常に一部取得と報告する。
- 保存は動画ID＋画像ハッシュ。タイトル変更やチャンネル名変更で重複フォルダを作らない。
- 一覧の種類で分類する。180秒以下という長さや画像の黒帯だけでShorts判定・削除しない。複数タブにあるIDは1つへまとめ、所属タブを併記する。
- 各動画の視聴ページを全件巡回しない。flat-playlistで日付等が欠けたらnull扱い。再生数も取得時点の値でありCTRではない。
- 標準は1秒以上の要求間隔・直列処理。403/429時は止めて記録する。アクセス制限を回避するための認証情報取得や大量再試行をしない。

## 実行

以下はパスとIDを実際の値へ置換する。Pythonは依存をインストールした環境のものを使う。

```bash
python3 SKILL_ROOT/scripts/collect_channel.py \
  --channel-id UCチャンネルID \
  --channel-name '確認済みの正式チャンネル名' \
  --source-url '確認したYouTubeチャンネルURL' \
  --out-dir DATA_ROOT/channels

python3 SKILL_ROOT/scripts/prepare_analysis.py \
  --channel-dir DATA_ROOT/channels/UCチャンネルID
```

画像は原寸・元バイトで保存し、低解像度しか得られない場合はwidth/heightへ実寸を記録する。404等では代替サイズへ進み、最大画質が常に取れると断言しない。取得済み画像はハッシュと画像デコードを検証する。破損時は再取得する。

スクリプト終了コード0は「指定タブの列挙範囲の画像保存完了」、2は「限定取得・未完了・中断」のいずれか。`collection_report.json` の詳細を読む。別の異常終了時もそれを成功と呼ばず、レポートとログを確認する。ネットワーク障害を「動画0件」と扱わない。

`listed_scope_complete: true` でも「公開一覧から列挙したN件の保存完了」と報告し、「非公開を含む全投稿を網羅」とは言わない。`all_requested_tabs_enumerated`、各タブのstatus、`enumerated_unique_this_run`、`saved_for_this_run`、`failed_or_pending_this_run` を照合する。警告を伴う列挙は保守的に未完了扱い。

中断時は同じコマンドで再実行する。画像は検証して再利用し、一覧は再列挙する（途中ページからの再開ではない）。一覧は100件ごと・タブ終了時、画像は1件ごとに保存する。強制終了で残る `.collection.lock` は他プロセスが動いていないことを確認してから解除する。

## 更新とサムネ差し替え

- 同じコマンドで新規IDを追加。既存画像は原則再ダウンロードしない。
- ユーザーが「差し替えられたサムネも更新」と指定した場合は `--refresh` を付ける。異なる画像ハッシュは別ファイルとなり、過去保存画像が残る。同じ画像は重複保存しない。
- 今回一覧から消えたIDの画像も削除しない。`last_seen_run` を用いて今回の一覧と過去アーカイブを区別する。
- 一覧のタブ分類は過去も含めた所属履歴。mixedとなった画像は目視確認後に制作参考として扱う。
- 自動の定期収集は設定しない。明示された更新依頼の範囲で実行する。

## 保存後の目視分析

収集スクリプトは画像の意味を分析しない。傾向分析はCodexが実画像を目視して行う。

1. `review_index.json` とページ別一覧を確認。全画像を俯瞰できるよう、すべての保存画像に対して一覧が作られている。大規模な場合はページ番号を分けて順に確認する。見ていないページが残ったら明記する。
2. 代表サンプルは各動画種類の「新着一覧18件」「取得できた再生数上位18件」「一覧全体から均等に18件」の和集合。最近の路線・過去の路線・人気偏重を分けて観察する。再生数順位がない動画を0再生として扱わない。これは統計的無作為標本ではない。
3. サンプルを原寸でも確認。テーマ・シリーズ・年代・構図の違いがあれば必要な追加動画を確認する。日付不明なら公開年代を断定せず「一覧上位・中位・下位」と表現する。
4. `observations.csv` の各サンプルに `inspected=yes` と観察を記入。未確認の行はnoのまま残す。列は次の基準で統一する。

| 列 | 記入する観察 |
|---|---|
| layout | 左文字右被写体 / 中央被写体 / 対比 / 写真全面 / その他の一貫したラベル |
| subject | 人物 / 商品 / 画面 / 料理 / 風景 / イラスト / 混合 / なし |
| text_amount | なし / 少 / 中 / 多（目視基準をanalysis.mdへ記す） |
| text_lines | 0 / 1 / 2 / 3 / 4以上 / unknown |
| palette | 主要な色2〜3色。必要なら原寸から近似HEXを別メモに記す |
| decoration | なし / 細フチ / 太フチ / 帯 / 矢印 / 複合など |
| copy_pattern | 疑問 / 数字 / ベネフィット / 比較 / テーマ名 / 文字なしなど |
| notes | 余白、人物位置、読順、シリーズ、例外、原寸参照など |

見えない項目はunknown、存在しないものはnoneなどとし、推測値で埋めない。

```bash
python3 SKILL_ROOT/scripts/prepare_analysis.py \
  --channel-dir DATA_ROOT/channels/UCチャンネルID \
  --observations DATA_ROOT/channels/UCチャンネルID/analysis/実行ID/observations.csv
```

5. `visual_summary.json` で確認済みサンプルだけの頻度と根拠IDを集計する。例えば「目視36枚中22枚が左文字・右人物」と書く。全保存枚数を目視母数に使わない。
6. `assets/channel-profile.template.json` を複製し、観察に基づく初期値を `channel-profile.json` へまとめる。`status` をdraft / learned / approvedで区別。目視済みでlearned、ユーザーがチャンネル方針を承認した場合にapprovedとする。承認なしにapprovedへしない。
7. `analysis.md` を下記の構成で完成させる。観察結果の羅列で終わらず、次の制作が再現できるルールへ変換する。

## analysis.md の構成

- 対象：正式名、URL、ID、確認日、収集実行ID。
- 範囲：列挙数、保存数、失敗数、動画種類、見た一覧ページ、原寸目視数、制約。
- 実際の傾向：構図、被写体比率、文字の量・字形・フチ、主要色、余白、背景、コピー。各項目に根拠IDと観察件数。
- 新旧・シリーズ差：古いスタイルやライブ告知を現行通常動画へ混ぜない。
- 次回の初稿ルール：位置・寸法比率の目安、色、字形、許容する余白、避ける装飾、参照2〜4枚。
- 例外と未確認：日付やCTRがない、画像が小さい、対象動画が少ない等。
- 提案：維持したい特徴と試したい変更を区別する。再生数のみで因果やCTR改善を断言しない。

チャンネル登録依頼の完了は、画像保存だけでなく根拠付きanalysis.mdと再利用可能なchannel-profile.jsonの作成まで。
