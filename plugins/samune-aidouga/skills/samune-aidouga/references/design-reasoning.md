# サムネイルの良さを具体的に判断する

2026-09-22更新。根拠は登録資料の実画像・PSD、ユーザーの採用と修正、[公開一次資料](sources.md)。一般の視覚デザイン原則をサムネへ応用する箇所は設計上の推論であり、このチャンネルでのCTR向上を実証した結果ではない。

## 判断の言い方

「かっこいい・インパクト・プロっぽい」で止めず、**どの要素の何が、何を理解しやすくするか**を説明する。例：「補足を白の単色、結果の数字を大きくし、まず短縮幅、その後に条件が読めるようにする。168px幅で単位と数字が離れて見えないか確かめる」。

`design-decision.json` の各案に、観察元ID、観察事実、今回への推論、具体的な処理、想定する読む順番、失敗条件を書く。参考にある収益額や断定コピーはデザインの観察対象であり、新しい動画の事実の根拠にはならない。

## 選ぶ順番

1. **意味**：対象視聴者が、この動画の対象と得られる内容を読み取れるか。タイトルとサムネは補完する。確定コピーは勝手に短縮しない。
2. **骨格**：ラフと企画の関係を保つ。比較は対応する対象を同格に、手順は順序を、実演は結果または実画面を、対談は発言と話者を対応させる。
3. **優先順位**：最初・次・補足の意味グループを決める。すべて同サイズ・同装飾にしない。文字サイズの種類を厳密に3個へ制限する意味ではない。
4. **字形と配色**：対象チャンネルの該当PSDから役割別に選ぶ。見出しの日本語、数字、単位、補足を別々に扱う。
5. **輪郭と背景**：背景との分離に必要な量だけフチ・影を選び、文字の内部がつぶれていないかを見る。装飾で優先順位の不備を隠さない。
6. **検査**：実画像を縮小して、狙った順で理解できるかを確かめる。雰囲気を再現できても文字・素材・指示違反があれば未完了。

## 操作と理由を結ぶ表

| 観点 | 観察・判断 | 制作に落とす項目 | 失敗の見つけ方 |
|---|---|---|---|
| 主役 | 最大の面積と最明部が読む順に影響する | 主役の面積、文字の字高、背景の明度分布 | 背景の発光点を最初に見てしまわないか |
| 意味のまとまり | 近いもの、同じ枠内のものを関連付けて読む | ロゴと説明の距離、帯、枠、列間隔 | 説明が隣のロゴに属して見えないか |
| 比較 | 同じ条件で並べると差を読み取りやすい | 元比率、視覚上の大きさ、整列、矢印の始終点 | 重要でない寸法差を性能差に見せていないか |
| 読む順 | 大きさ・明度・色・位置に役割がある | 導入→結果、主体→用途等を明示 | すべてが同時に主張し内容が定まらないか |
| 字形 | 同じゴシックでも字面・懐・かな・数字が違う | 実フォント名、ウェイト、混植、字間 | 誤字、横つぶし、濁点、内部の白い空間を原寸比較 |
| フチ | 明暗が変わる背景でも輪郭を保持する | 内外の順序、色、幅、角、位置 | 小さな文字の中が塞がる、白フチが太すぎる |
| 影 | 対象を背景から分離する、厚みを示す | 色、不透明度、距離、角度、ぼかし、spread/choke | 二重文字・黒い泥・無関係な光源に見えないか |
| グラデーション | 主見出しに素材感・立体感を与える | 停止位置、色、角度、透明度、クリッピング | 単色に戻る、明暗帯が文字を分断する、補足へ波及 |
| 背景 | 主役の文脈と、文字を置く静かな領域を作る | 密度、色温度、被写界深度、明暗、光源 | 文字裏の線が字画と混ざる、過去背景そのものの複製 |
| 人物・キャラ | 視線や手元が対象を説明する | 元素材、トリミング、視線先、手、道具、輪郭光 | 別人化、顔への文字かぶり、道具や指の破綻 |
| ロゴ | ブランドを正確に識別させる | 実素材、内部形状、色、元比率、タイルと余白 | よく似た偽マーク、形を揃えるための変形 |
| 隠す表現 | 何が隠されているかの期待を調節する | 対象範囲と認識のしづらさ | 強いブラー指定なのにロゴが読める、周囲の文字までぼける |

影のchoke/spreadをフチ幅pxと取り違えない。PSDの生値は制作面の寸法、レイヤー変換、親グループ、効果スケールとセットで読む。距離0の影による輪郭とStrokeを見た目だけで同一設定にしない。ラスタライズ済みの金属素材を、存在しないGradientOverlay値として記録しない。

## 企画ごとの引き出し

| 企画 | 有効な骨格と文字処理 | 勝手に加えないもの |
|---|---|---|
| ツール比較 | 同格のロゴ枠、対応する説明、差を示す数字 | 順位・王冠・勝敗の断定 |
| 工程の自動化 | 実画面、機能ラベル、結果数字 | 実演していないUIや自動化範囲 |
| 前後の改善 | 同じ単位の数字、比較方向が明確な矢印 | 元資料の成果数値 |
| 現場検証 | 実人物と作業環境、簡素な補足、問いを主役に | 無関係な宇宙背景やAI美女 |
| 対談・密着 | 実人物の関係、発言と話者、下段結論 | 別人の顔、全員の誇張表情 |
| 警告・告知 | 強い主語・結論、赤や明朝／太ゴシックの該当例 | 「警告なら必ず明朝」という固定化 |
| 教科書・まとめ | 大きな対象語、選数、対応する作例群 | 読めない小情報の詰め込み |
| 正体を伏せる | 見せる情報と隠す情報の差、周囲は明瞭 | 意味のない全面ぼかし |
| 配信案内 | 主題・出演者・日時を区別した帯 | 通常動画へ無関係な日時帯を追加 |

## 選択した作風に適用する

対象のプロファイルと根拠画像から字形・効果・配色・整列を決める。利用者がPSDや書体資料を提供した場合は実設定を優先する。PSDがない時に正確なフォント名や効果の数値を断定しない。

補足、主見出し、数字は別項目で管理し、今回の指定外へ加工を波及させない。ロゴは利用者の正式素材を使い、参考チャンネルから借用しない。今回だけの調整を別案件・別チャンネルへ自動適用しない。

## 採用しない安易な法則

「サムネは必ず3語」「顔は必須」「全て黄赤」「フォントは絶対2種」「全画像に光彩」「公開再生数が高いからこの影はCTRが高い」は採用しない。媒体向けの一般論より、今回のラフ・指示と対応PSDを優先する。公開資料の文字数・配色数は設計の目安であり、確定コピーを削る根拠ではない。

初回3案は、ユーザーの選択肢を確保するルールでもある。効果検証を行う場合は何の見せ方を比較したいかを1文で残す。YouTube公式の比較はCTRだけでなく視聴時間の割合も用いるため、結果未取得の段階で「勝ち案」と呼ばない。投稿・Studio操作はユーザーが行う。
