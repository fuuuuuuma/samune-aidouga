# 過去の修正から作った再発防止

根拠となる画像・発言・数値はデータ側のcorrectionsとacceptanceを読む。ここでは個人素材を同梱せず、他案件にも使える検査手順だけを共通化する。

| 過去の指摘 | 根本原因として防ぐもの | 毎回の扱い |
|---|---|---|
| スラッシュ内が派手 | 補足と主見出しを同じスタイルで処理 | ブロック別にフォント・塗り・影を定義。主チャンネルの補足は単色白ゴシックが基本 |
| ロゴが偽物っぽい | 過去の加工例や名前から形を再生成 | 提供原図と照合。形・内部抜き・比率を固定し、統一感は周囲で作る |
| Claudeの配色が違う | 一般ブランドの別配色を今回の指定より優先 | この主チャンネルではオレンジ地＋白マーク。別案件の明示指示はそちらが優先 |
| 完全無料を全高にしたらグラデーションが消えた | 配置の修正で塗りを省略 | 位置・字高と塗り・色停止位置を独立固定。全高でも上下を切らない |
| ×を薄くしたら細くなった | 太さと透明度を同じ曖昧な指示にする | 線幅とopacityを別項目化し、両方をQC。65%は当該案件のみ |
| Antigravityがまだ分かる | ブラーの量だけ指定し、認識目標を確認しない | 当該案件ではロゴ全域を特定しづらく。文字と周囲をぼかさない |
| 上段を小さく、下段と数字を大きく | 二行全体を一括拡縮 | 導入・結果日本語・数字・単位を別々に調整。10hを10時間へ勝手に改稿しない |
| 1hの赤パターンも欲しい | 一部色違いのため全体を再解釈 | 対象1hのみ色を変更。他の塗り・レイアウト・太い×を保持 |
| 他は絶対に変更しない | 新規制作と限定編集の混同 | 変更箇所を列挙し、元画像と差分を目視。JSON一致だけで安心しない |
| 同じ背景を使わない | 作風の再利用と背景画像の複製を混同 | 新規制作は新しい背景。限定修正では承認済み背景を維持する |
| 指示していない女性の顔までアップになった | 人物別の許可をまとめて全人物へ適用 | 顔アップ・クロップは人物ごとに変更許可を記録。指示のない人物は採用稿の顔サイズと上半身の見え方を保持する |
| 文字を以前へ戻したい、参考通りの品質にならない | 元の装飾を一般フォントへ置換し、参考フォントを確認しない | 復元は採用稿の字形・塗り・縁・影を基準にする。再制作はPSDの実フォントと効果を確認。人物保持のため文字と写真を分けても、装飾の無断簡略化はしない |

案件の65%は、生成済みの合成画像からレイヤーの正確な不透明度を測れた意味ではない。設定値を持つ素材なら実数で確認し、画像生成だけなら「65%程度の見た目」を原図と比較する。線幅も元画像の解像度とセットで記録する。

修正2案で一方だけ条件を満たす状態にしない。「完全無料の全高」と「1h赤」などの累積指示は、最後の一文だけに要約せず保持する。過去にOKとなった画像に誤りが見えても、今回の変更禁止を破って黙って全面修正しない。

完全な同一ピクセル保持が必要で、現在の画像編集手段で保護できない場合は、限定編集と比較を試してから残る差を正直に示す。「絶対に変えていない」と検証なしに報告しない。画像編集の手段は利用環境の上位指示に従い、禁止されるPython合成等へ迂回しない。


## 全案件共通の再発防止
- スラッシュ囲みはテキストとブロックを左端の基準線へそろえる。中央寄せの枠の中で左詰めにするだけでは不十分。
- 人物入りは専用写真の有無を確認してから生成する。
- 最新依頼・過去FB・採用条件の突き合わせを生成前に記録する。
- 納品実寸は3840×2160。プロンプトの数値ではなくファイルヘッダーで検証。詳細はglobal-feedback.md。
- 「OK」になった番号は再生成・再圧縮せず、納品ファイルのSHA-256が一致する形で引き継ぐ。文字と人物の復元は個別の採用稿を特定してから行う。
